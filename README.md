# Side Tests

A QA test automation project for validating SIDE.INC web application through structured manual and automated testing. This repository is used to organize test assets, scripts, documentation, and reports in one place.

## Overview

`side-tests` contains test resources that support software quality activities, including:
- Manual test case design and execution.
- Automated UI and API tests.
- Regression and smoke testing.
- Test data management.
- Defect reporting and validation.
- Test documentation and reporting.

## Features

- Organized test suites and scenarios.
- Support for automated and manual testing.
- Clear separation of test data, scripts, and reports.
- Reusable utilities and helper functions.
- Easy maintenance and expansion of test coverage.
- Suitable for web, API, and integration testing.

## Project Structure

```text
side-tests/
├── tests/            # Test cases and automation scripts
├── test-data/        # Sample data and fixtures
├── reports/          # Test execution outputs
├── docs/             # Supporting documents and notes
├── utils/            # Shared helpers and reusable code
└── README.md
```

## Requirements

Depending on the framework used in this project, you may need:
- Node.js or Python.
- A browser automation framework such as Playwright or Selenium.
- Git for version control.
- Any required environment variables or credentials for the test system.

## Getting Started

### 1. Clone the repository

```bash
git clone <repository-url>
cd side-tests
```

### 2. Install dependencies

If using Node.js:

```bash
npm install
```

If using Python:

```bash
pip install -r requirements.txt
```

### 3. Configure test environment

Create and update environment settings as needed:

```bash
cp .env.example .env
```

Add base URLs, credentials, and other required values.

### 4. Run tests

Examples:

```bash
npm test
```

or

```bash
pytest
```

## Reports

Test reports should be stored in the `reports/` directory or generated by the selected test runner. These reports help track execution results, failures, and trends over time.

## Best Practices

- Keep tests independent and readable.
- Use meaningful names for test cases and files.
- Reuse utilities where possible.
- Keep test data separate from logic.
- Update documentation when workflows change.

## Contributing

When adding or updating tests:
1. Create a new branch.
2. Add or modify the required test files.
3. Run the relevant test suite locally.
4. Submit a pull request with a clear summary of the changes.
